### 2.1 The `useData()` contract (frozen inside Lane D at 6:00 PM)
```ts
// src/data/types.ts: field names come from CONTRACTS §3.1. u64 values become number in the UI.
export interface FacilityRow { id: number; name: string; template: string; seed: number; tick: number; sim_time_s: number; status: string }
export interface ComponentRow { id: string; kind: 'utility'|'ups'|'pump'|'rack'; label: string; status: string; params: Record<string, number>; is_real_hardware: boolean; x: number; y: number }
export interface EdgeRow { id: number; from_id: string; to_id: string; kind: 'power'|'cooling' }
export interface TelemetryLatestRow { component_id: string; tick: number; temp_c: number; power_kw: number; cooling_kw: number; load_kw: number; ups_energy_kwh: number; fan_health: number; fan_anomaly: number; fan_online: boolean; sensor_age_s: number }
export interface TelemetryHistoryRow { id: number; component_id: string; tick: number; temp_c: number; power_kw: number; cooling_kw: number }
export interface TicketRow { id: number; component_id: string; title: string; status: string; notes: string; created_tick: number }
export interface ShiftNoteRow { id: number; author: string; body: string; verified: boolean; tick: number }
export interface IncidentRow { id: number; opened_tick: number; symptom: string; component_ids: string[]; severity: string; status: string; hypothesis: string; chosen_plan: PlanDecision | null; resolved_tick: number }
export interface ActionRow { id: number; requested_by: string; kind: string; target_id: string; params: { kw?: number; to?: string }; status: string; safety_reason: string; predicted: Outcome | null; incident_id: number; tick: number }
export interface AgentStepRow { id: number; incident_id: number; agent: string; step_no: number; kind: string; tool: string; summary: string; payload: unknown; tick: number }
export interface Outcome { min_cooling_margin_kw: number; peak_temp_c: number; racks_degraded: number; racks_shutdown: number; downtime_rack_s: number }
export interface PlanDecision { plans: { name: string; actions: { kind: string; target_id: string; params: { kw?: number; to?: string } }[]; outcome: Outcome }[]; chosen: number; reason: string }

export interface DataApi {
  mode: 'fixture' | 'live' | 'http';
  conn: 'connecting' | 'connected' | 'error';
  error?: string;
  facility: FacilityRow | null;
  components: ComponentRow[]; edges: EdgeRow[];
  latest: Record<string, TelemetryLatestRow>;
  history: TelemetryHistoryRow[];           // every component; ≤120 rows each
  tickets: TicketRow[]; shiftNotes: ShiftNoteRow[];
  incidents: IncidentRow[]; actions: ActionRow[]; agentSteps: AgentStepRow[];
  metrics: Record<string, number>;          // keys from METRIC_KEYS
  reducers: {
    seedDemoFacility(): Promise<void>;
    buildFacility(configJson: string): Promise<void>;
    injectFailure(kind: string, targetId: string, paramsJson: string): Promise<void>;
    clearFailure(failureId: number): Promise<void>;
    requestAction(kind: string, targetId: string, paramsJson: string, requestedBy: string, incidentId: number): Promise<void>;
    executeAction(actionId: number): Promise<void>;
    setRunConfig(paused: boolean, speed: number): Promise<void>;
  };
}
```
- **Parse every `*_json` column once, in `normalize.ts`,** inside try/catch. On a parse failure, store `null` and `console.warn` once.
- `component_ids` arrives as a CSV string; split it in the normalizer.
- `VITE_DATA_MODE=fixture|live|http` picks the source. The default is `fixture` until 7:00 PM and `live` after that.
- **Binding names:** use whatever the generated bindings expose (e.g. `componentId`, `simTimeS`, `db.telemetryLatest`, `reducers.seedDemoFacility`). **Only `normalize.ts`, `liveSource.ts` and `reducers.ts` know those names.** Never hand-edit the bindings. Convert bigints with `Number(x)`.
- **Live connection:** `stdb.tsx` builds the connection with the generated `DbConnection.builder()`: `.withUri(VITE_STDB_URI)`, the database name (`VITE_STDB_DB`; the builder method may be `withDatabaseName` or `withModuleName` depending on the SDK version, so check the bindings), `.withToken(presenterToken | stored anon token)`, and `onConnect` → `subscribe(['SELECT * FROM facility', 'SELECT * FROM component', …every public table])`. Wrap the app in `SpacetimeDBProvider`. Read tables with `useTable`, and call reducers with `useReducer` or `conn.reducers.*`. **Confirm the exact hook signatures against the SDK version S installs at 7:00 PM.**
- **Reducer errors:** `FORBIDDEN:`, `NOT_FOUND:` and `INVALID:` come back as rejected promises or error events. Show them as a toast with the raw message. Never swallow them.

## 3. Visual rules (apply to every component)

- **Theme:** a dark "command center".
  - Background `#0B0F14`, panels `#121821`, borders `#1F2A37`, text `#E6EDF3`, muted text `#8B98A5`.
  - Monospace numerals: `font-variant-numeric: tabular-nums`, with JetBrains Mono or IBM Plex Mono for numbers.
  - Inter or Geist for the rest of the text.
- **Readable at 2 m:**
  - body text ≥ 16 px;
  - key numbers (temperatures, margin, anomaly) ≥ 28 px;
  - panel titles 14 px uppercase, letter-spaced;
  - at most 3 font sizes per panel.
- **Status = color + text label + icon. Never color alone.**

  | Status / condition | Color | Label |
  |---|---|---|
  | `online` | green `#22C55E` | ONLINE |
  | temp ≥ `T_WARNING_C` (35) | amber `#F59E0B` | WARNING |
  | `degraded` (or ≥ 45 °C) | orange `#F97316` | DEGRADED |
  | `offline` | red `#EF4444` | OFFLINE |
  | `shutdown` (≥ 55 °C) | red `#B91C1C`, striped | SHUTDOWN |
  | `maintenance` | blue `#3B82F6` | MAINT |
  | stale sensor (`sensor_age_s` > 15) | grey dashed outline | STALE n s |

  Put this mapping in `lib/status.ts`. Import the thresholds from `@dcos/physics` constants if you can; otherwise copy them with a comment pointing to CONTRACTS §1.
- **Badges (CONTRACTS §7):**
  - **REAL HARDWARE**: magenta pill `#D946EF` on any node or panel where `component.is_real_hardware` is true (rack_3).
  - **REPLAY OF REAL RECORDING**: amber pill, shown when the bridge's `fault_class` starts with `replay:`. Needs the contract gap in §12 closed; until then it's hidden.
  - **REAL FAN OFFLINE**: grey pill when `fan_online=false`.
- **Motion:** only meaningful motion.
  - Edges animate while their source is online.
  - A new agent step slides in over 150 ms.
  - A status change pulses once.
  - No looping glow.
- **Layout:** 1920×1080 first, because the demo laptop drives an external monitor. It must also look acceptable at 1440×900 and stack to a single column on phones (≤ 640 px).

## 12. Proposed contract requests (file as `CONTRACT D: …` issues for S)
1. **Fan fault class + RMS are not public.** `report_fan_reading` takes `fault_class` and `rms`, but no public column stores them, so the UI can't show "imbalance" or the **REPLAY OF REAL RECORDING** badge that CONTRACTS §7 requires. Proposed additive fix: `telemetry_latest.fan_fault_class: string` (default `''`) and `fan_rms: f64` (default 0).
2. **`clear_failure(failure_id)` is unusable from the UI.** The `failure` table is private, so the presenter can't learn the ids. Proposed: a `clear_all_failures()` reducer (admin, presenter), or return the id via a public `active_failure_id` metric. Otherwise the presenter "Clear" button relies on Reset demo.
3. **Eval numbers for the UI.** Ask S to also commit `eval/results/summary.json` (the headline numbers), so the Results page and slides don't retype the CSV by hand.
4. **Lockfile ownership.** Confirm that D may commit `pnpm-lock.yaml` changes caused by `apps/web` deps, or that S regenerates it at merge.
5. **Fan anomaly history.** `telemetry_history` has no `fan_anomaly`, so the fan sparkline is a client-side buffer that resets on reload. Optional additive `fan_anomaly: f64` on `telemetry_history`.
6. **CORS on the Maincloud HTTP SQL endpoint** for the `http` fallback mode: S to confirm at the booth.
